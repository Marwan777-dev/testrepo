Part 1 — Module 06: CX Metrics &amp; KPI Engine
1. Introduction
1.1 Purpose &amp; Audience
This document specifies the KPI Management and KPI Configuration surfaces of the CX Metrics &amp; KPI Engine module (M-06), and the Platform Settings page (Part 2), for the Nabadat VOC platform. It is the single source of truth for engineering, QA, design, and product teams building these pages.
Audience: Backend engineers, frontend engineers, QA engineers, UX designers, product managers, CX consultants.
This document assumes no prior CX domain knowledge. Every CX/VOC term is defined on first use and consolidated in the Glossary (Section 10).
Scope note: M-06 is responsible for KPI definition and score computation. This document covers the KPI definition surfaces only — the screens where a CX Program Manager creates, configures, activates, and manages the catalogue of KPIs. The computation engine and the consumption of these definitions by M-16 journey scoring are referenced but specified elsewhere.
1.2 Scope
In scope (this document):
The KPI Management page — the catalogue list of all KPIs (standard + custom)
The KPI Configuration page — the create/edit surface for a single KPI
KPI attribute definitions: short name, full name, perspectives, calculation method, scale, representation style, thresholds, target, activation, dashboard visibility
Live preview behaviour (question preview + KPI visualization gauge)
The CXI composite KPI special configuration variant
Standard vs custom KPI editability rules
Validation rules and error messaging
Permissions for KPI management
Localization (Arabic + English, RTL)
Platform Settings page (Part 2): Organization section + Customer Journey scoring configuration

Out of scope (this document):
Score computation execution at scale (the engine that processes responses into scores)
Multi-level aggregation (touchpoint/stage/journey) — owned by M-16 Strategic Scoring Model
KPI weight assignment per touchpoint — configured in M-16, not here
Survey question authoring and binding of questions to KPIs — handled in M-01
Dashboard rendering of KPI scores — handled in M-07
Metric trend computation and threshold/target alerting — handled by M-07 and M-09 respectively
1.3 Definitions &amp; Acronyms
Term
Definition
KPI
Key Performance Indicator. A configurable CX metric (NPS, CSAT, CES, etc.). M-06 owns its definition and computation.
Standard KPI
A platform-provided KPI pre-loaded at tenant provisioning. Cannot be deleted; has constrained editability.
Custom KPI
A tenant-created KPI. Fully configurable except short name after creation.

CSAT
Customer Satisfaction Score. Post-interaction rating.
CES
Customer Effort Score. Ease-of-interaction metric; lower effort = better.
CXI
Customer Experience Index. A composite KPI derived from a weighted combination of other active KPIs.
FCR
First Contact Resolution.
VFM
Value for Money. Measures customer satisfaction with the price paid relative to the value gained post-transaction. User-configured scale and calculation method.
CHS
Customer Happiness Score. Measures customer happiness post-transaction (common in the sports and entertainment sector). User-configured scale and calculation method.
Agent Score
Measures customer satisfaction with the frontliner's behaviour post-transaction — typically across professionalism, attitude, and appearance perspectives. Survey-derived. User-configured scale and calculation method.
Calculation Method
The algorithm used to derive the KPI score: Weighted Average, TOP n Box, NPS Standard, or Weighted Composite (CXI).
Scale
The raw response range of the KPI (e.g., 1–5, 0–10).
Representation Style
How the scale is presented to respondents: Number, Stars, Emoji, or Slider.
Threshold
The three satisfaction bands (Unsatisfactory / Average / Satisfactory) applied to the normalised score.
Target
The goal value the tenant aims to achieve for this KPI.
Normalised Score
A raw KPI value mapped to a 0–100 index (NPS excepted — it displays raw −100 to +100).
Tenant
A client organisation using Nabadat; all KPI data is isolated per tenant.

2. Overall Description
2.1 Product Perspective
M-06 is a Phase 1 core module. The KPI definitions configured here are foundational inputs consumed by M-16 (journey scoring), M-01 (survey question binding), and M-07 (dashboard display).
Module interactions:
M-16 Customer Journey Mapping (consumer): Reads active KPI definitions, scales, normalisation rules, and calculation methods. Binds KPIs to touchpoints with per-touchpoint weights (owned by M-16). The KPI list surfaced in M-16's touchpoint KPI picker is the set of active KPIs defined here.
M-01 Survey and Form Builder (consumer): Binds survey questions to KPIs. Uses the KPI scale and representation style to render questions consistently with the preview shown here.
M-07 Dashboards &amp; Reporting (consumer): Renders KPI scores using each KPI's threshold bands and visualization form. Consumes the Show-on-Main-Dashboard flag to decide which KPIs appear as summary cards.
M-09 Notifications &amp; Alerts (consumer): Uses target and threshold definitions to fire alerts when scores cross bands or miss targets.
M-10 User &amp; Role Management (foundational): Provides the RBAC primitives gating who may manage KPIs.
M-11 Tenant Administration (foundational): Provides tenant isolation and the audit log infrastructure for KPI configuration changes.
This module owns the entities: KPIDefinition, KPIThreshold, KPIPerspective, and the composite-specific CXIWeight.
2.2 Operating Environment
Responsive: desktop primary; the two-panel config layout collapses to stacked (form above preview) on narrow viewports.
Navigation: KPI Management appears under the PLATFORM section of the left navigation.
2.3 Assumptions &amp; Dependencies
A1: M-10 is operational; the CX Program Manager (P-01) role is the primary actor for KPI management.
A2: M-11 is operational; tenant provisioning seeds the eight standard KPIs and the audit log is available.
A3: The normalisation formulas (Section 9) are applied by the M-06 computation engine, consistent with M-16 Section 3.3.4.
A4: Eight standard KPIs are seeded at provisioning (NPS, CSAT, CES, CXI, FCR, VFM, Agent Score, CHS). CHS, VFM, and Agent Score are fully user-configurable like any other KPI; Agent Score is survey-derived. See Section 3.1.4.

3. System Features
3.1 F1 — KPI Management Page
3.1.1 Description &amp; Priority
The central catalogue of all KPIs available to the tenant — both standard and custom. The entry point to all KPI configuration and the only place where new KPIs are created. Priority: Must-have.
NOTE  UI reference: Image 1 shows the KPI Management page at route /kpi-management: page title with live &quot;8 Active KPIs&quot; subtitle, a Type filter dropdown, an &quot;Active only&quot; checkbox, a search box, an &quot;+ Add KPI&quot; primary button, and the KPI table.
3.1.2 Functional Requirements
FR-1.1: The page header displays a live count subtitle: &quot;[X] Active KPIs&quot;. The count reflects only KPIs with status = Active and updates immediately on any activation/deactivation without a page refresh.
FR-1.2: A Type filter dropdown with options: All (default), Standard, Custom. Filters the table by KPI type.
FR-1.3: An &quot;Active only&quot; checkbox (checked by default). When checked, only Active KPIs are listed. When unchecked, all KPIs appear, with inactive rows visually dimmed.
FR-1.4: A Search box filtering the list in real time by Short Name or Full Name (case-insensitive substring match).
FR-1.5: A &quot;+ Add KPI&quot; primary button opening the KPI Configuration page in create mode (empty form, type = Custom, title &quot;New KPI&quot;).
FR-1.6: The KPI table displays columns: Short Name, Full Name, Type, Scale, Calc. Method, Target, Dashboard, Status.
FR-1.7: The Short Name cell is rendered as a clickable link (teal). Clicking any row navigates to the KPI Configuration page for that KPI in edit mode.
FR-1.8: The Type column renders a pill badge: &quot;Standard&quot; (filled teal-tint) or &quot;Custom&quot; (outlined).
FR-1.9: The Scale column shows the configured raw scale (e.g., 1–5, 0–10). Composite KPIs (CXI) show &quot;—&quot;.
FR-1.10: The Calc. Method column shows the human-readable method: &quot;NPS Standard&quot;, &quot;Weighted Average&quot;, or &quot;Weighted Composite&quot;.
FR-1.11: The Dashboard column renders a checked box icon when Show-on-Main-Dashboard is enabled, or &quot;—&quot; when not.
FR-1.12: The Status column renders a coloured dot + label: green &quot;Active&quot; or grey &quot;Inactive&quot;.
FR-1.13: Standard KPIs are listed first in a fixed canonical order (NPS, CSAT, CES, CXI, FCR, VFM, Agent Score, CHS), followed by custom KPIs sorted by creation date descending.
FR-1.14: No KPI may be deleted. No delete control exists on any row, and no delete endpoint is exposed. KPIs are removed from active use only by deactivation.
3.1.3 Business Rules
BR-1.1: The eight standard KPIs are always present regardless of status and cannot be removed from the catalogue.
BR-1.2: Short Name uniqueness is enforced per tenant (case-insensitive, trimmed) across both standard and custom KPIs.
BR-1.3: The &quot;Active KPIs&quot; count in the header counts every KPI with status = Active, including CXI.

3.2 F2 — KPI Configuration Page (Create / Edit)
3.2.1 Description &amp; Priority
The create/edit surface for a single KPI. A two-panel layout: configuration form on the left, live preview on the right. Opened via &quot;+ Add KPI&quot; (create mode, titled &quot;New KPI&quot;) or by clicking a KPI row (edit mode, titled &quot;KPI Configuration&quot; with the full name as subtitle). Priority: Must-have.
NOTE  UI reference: Image 2 shows create mode (&quot;New KPI&quot;) with an Emoji representation revealing an &quot;Emoji Set&quot; dropdown and a 1–7 emoji question preview; the gauge defaults to 50 with a &quot;KPI&quot; label and Save disabled. Image 3 shows edit mode for NPS: Short Name, Calculation Method, and Scale are read-only; thresholds run −100 to +100; the gauge shows +42 with an &quot;NPS&quot; label and Save enabled.
3.2.2 Layout Requirements
FR-2.1: The page is split into two panels: left = configuration form (≈55% width), right = live preview (≈45% width).
FR-2.2: The right preview panel contains two stacked cards: Question Preview (top) and Dashboard Preview (bottom). The Dashboard Preview shows how the KPI's score card will render in M-07.
FR-2.3: Both preview cards update live as the user edits any relevant field — no save required.
FR-2.4: On viewports narrower than the tablet breakpoint, the panels stack vertically with the form above the preview.
FR-2.5: A back arrow in the page header returns to the KPI Management list, applying the unsaved-changes guard by viewing a confirmation message asking to save or discard changes (FR-2.46).
3.2.3 Functional Requirements — Configuration Form Fields
Field 1 — Short Name
FR-2.6: Text input, max 20 characters, required, placeholder &quot;e.g. QUAL&quot;.
FR-2.7: Must be unique per tenant (case-insensitive, trimmed); validated on blur with inline error: &quot;This short name is already in use.&quot;
FR-2.8: Immutable after first save. In edit mode it renders as a read-only, visually greyed field with an info icon; tooltip: &quot;Short name cannot be changed after creation.&quot;
FR-2.9: Updates the KPI label inside the visualization gauge in real time (create mode).
Field 2 — Full Name
FR-2.10: Text input, max 100 characters, required.
FR-2.11: Updates the Question Preview question label in real time.
Field 3 — Perspectives
FR-2.12: Tag/chip input; the user types a label and presses Enter or comma to add it. Helper text: &quot;Press Enter or comma to add. Max 10.&quot;
FR-2.13: Each chip is removable (× icon). Max 10 perspectives; max 60 characters each. Each perspective is a drill-down dimension of the KPI (e.g., for Agent Score: Attitude, Knowledge, Willingness to Help).
FR-2.14: Perspectives are independent drill-down dimensions, not a decomposition of the headline score. The overall KPI score is computed solely from the KPI's own question(s); it is NOT an arithmetic roll-up (average or weighted sum) of perspective scores.
FR-2.14a: Each perspective is independently scored from its own survey question(s) bound to that perspective in M-01, using the KPI's scale and calculation method. M-06 computes and stores a score per perspective alongside the KPI's own overall score.
FR-2.14b: In M-07 reporting, the user can view the KPI both at the overall level (regardless of perspective) and broken down by each perspective. Perspectives are optional; a KPI with no perspectives simply has no drill-down slices.
Field 4 — Calculation Method
FR-2.15: Dropdown, required. Options: Weighted Average, TOP n Box, NPS Standard.
FR-2.16: Selecting TOP n Box reveals an integer n value input. n must be a positive integer strictly less than the maximum value of the chosen scale (e.g., for a 1–7 scale, n may be 1–6; for a 0–10 scale, n may be 1–9). Definition: the percentage of respondents selecting one of the top n scale values. Values of n equal to or above the scale maximum are rejected with inline error: &quot;n must be less than the maximum scale value.&quot;
FR-2.17: A non-blocking warning appears when n &gt; ½ × (number of distinct scale values − 1). Here &quot;number of scale values&quot; means the count of distinct selectable points on the scale (e.g., 7 for a 1–7 scale, 11 for a 0–10 scale) — not the three threshold bands. Warning text: &quot;Using a high n value may overstate satisfaction. Consider a stricter threshold.&quot; The user may proceed.
FR-2.18: NPS Standard is selectable/visible only for the NPS KPI; hidden for all others. For NPS it is read-only and shown with helper text below: &quot;Score = % Promoters (9–10) − % Detractors (0–6)&quot;.
FR-2.19: For standard KPIs whose method is fixed (NPS), the field renders read-only. Custom KPIs may select any method except NPS Standard.
Field 5 — Scale
FR-2.20: Dropdown, required. Options: 0–10, 1–3, 1–5, 1–7, 1–10, 1–100.
FR-2.21: For NPS, locked to 0–10 and rendered read-only with label &quot;0–10 (locked for NPS)&quot;.
FR-2.22: Changing the scale updates the Question Preview immediately (the response control re-renders for the new range and current representation style).
FR-2.23: Changing the scale on a KPI already bound to active touchpoints in M-16 triggers a blocking confirmation: &quot;Changing the scale will affect [N] active touchpoints and their historical normalisation. This is a structural change. Continue?&quot;
Field 5a — Scale Endpoint Descriptions (Minimum / Maximum Scale Description)
FR-2.23a: Two optional free-text fields — Minimum Scale Description and Maximum Scale Description — let the user label the low and high ends of the scale (e.g., NPS: &quot;Definitely Would Not Recommend&quot; / &quot;Definitely Would Recommend&quot;). Max 60 characters each. Both are bilingual (EN + AR).
FR-2.23b: These descriptions render as the left/right anchor labels beneath the scale in the Question Preview (see FR-3.15) and accompany the question wherever it is rendered by M-01. They are display labels only and do not affect scoring.
Field 6 — Representation Style
FR-2.24: Dropdown, required. Options: Number, Stars, Emoji, Slider.
FR-2.25: Selecting Emoji reveals a secondary Emoji Set dropdown. The confirmed v1 catalogue is: FaceClassic (graduated faces 😞 → 😍), and at least one additional set (e.g., a hand/thumbs set 👎 ✋ 👍). Each set maps one emoji per scale value; the chosen set renders in the Question Preview.
FR-2.26: Slider is selectable only when scale = 1–3. If the scale changes away from 1–3 while Slider is active, the style resets to Number with tooltip: &quot;Slider is only available for 1–3 scales.&quot;
FR-2.27: The emoji preview renders one emoji per scale value (e.g., 7 faces for a 1–7 scale).
FR-2.28: Changing the representation style (and emoji set) updates the Question Preview immediately.
Field 7 — Threshold Configuration
FR-2.29: Three labelled rows defining contiguous satisfaction bands: Unsatisfactory (lower ≤ score ≤ x), Average (x &lt; score ≤ y), Satisfactory (y &lt; score ≤ upper).
FR-2.30: x and y are editable integer inputs. The lower bound (0, or −100 for NPS) and upper bound (100, or +100 for NPS) are fixed, non-editable display values.
FR-2.31: Defaults on create: x = 20, y = 70.
FR-2.32: Validation: lower &lt; x &lt; y &lt; upper. Inline error on violation: &quot;Threshold values must be ascending and within range.&quot;
FR-2.33: Band labels are colour-coded: Unsatisfactory red, Average amber, Satisfactory green.
FR-2.34: Editing x or y repositions the gauge colour-band boundaries in real time.
Field 8 — Target
FR-2.35: Integer input. Required for active KPIs.
FR-2.36: Range 0–100 for all KPIs except NPS; range −100 to +100 for NPS. Out-of-range is a blocking inline error: &quot;Target must be between [min] and [max].&quot;
FR-2.37: Non-blocking warning if the target is below the Satisfactory band (&lt; y): &quot;This target is not within the Satisfactory range.&quot;
FR-2.38: The target renders as a coloured marker (▼) on the gauge in real time.
Field 9 — Active
FR-2.39: Checkbox, default checked on create. Unchecking excludes the KPI from future scoring, M-16 bindings, survey distributions, and M-07 reporting; historical data is preserved.
FR-2.40: If the KPI is bound to active touchpoints, unchecking triggers a blocking confirmation: &quot;This KPI is bound to [N] active touchpoints across [M] journeys. Deactivating excludes it from future scoring. Existing data is preserved. Continue?&quot;
FR-2.41: Deactivating auto-unchecks and disables Show-on-Main-Dashboard, and removes the KPI from any CXI weight table (recomputing CXI proportions).
Field 10 — Show on Main Dashboard
FR-2.42: Checkbox, default unchecked. Enabled only when Active is checked.
FR-2.43: When checked, the KPI appears as a summary card on the M-07 main dashboard. When unchecked, it remains available in M-07 drill-downs but not as a summary card.
3.2.4 Functional Requirements — Form Actions
FR-2.44: Save validates all fields; on success, persists and returns to the KPI Management list; on failure, shows inline errors without navigating.
FR-2.45: Save is disabled until all required fields are valid: Short Name, Full Name, Calculation Method, Scale, Threshold x, Threshold y (Target required additionally when Active). The disabled state is visually distinct.
FR-2.46: Cancel discards changes and returns to the list, guarded by an unsaved-changes confirmation when changes exist: &quot;You have unsaved changes. Are you sure you want to leave?&quot;
FR-2.47: Every create/edit/activate/deactivate is written to the M-11 audit log with actor, timestamp, field, previous value, and new value.
3.2.5 Business Rules
BR-2.1: Immutable-after-create fields: Short Name (all KPIs). Immutable-for-standard fields: Scale and Calculation Method for NPS.
BR-2.2: Thresholds and target apply to the normalised 0–100 score for all KPIs except NPS, where they apply to the raw −100 to +100 score.
BR-2.3: A weight of 0 (in TOP n Box n, or CXI weights) is treated as not configured.

3.3 F3 — Live Preview
3.3.1 Description &amp; Priority
Two live preview cards on the right panel give the user immediate feedback on how the KPI will appear to respondents and on dashboards. Priority: Must-have.
3.3.2 Functional Requirements — Question Preview
FR-3.1: Displays a placeholder question label appropriate to the KPI; defaults to &quot;Rate your experience with ….&quot; and updates to a KPI-specific prompt where known (e.g., NPS: &quot;How likely are you to recommend us to a friend or colleague?&quot;).
FR-3.2: Renders the scale in the selected representation style: Number (numbered chips), Stars, Emoji (one emoji per scale value from the selected set), or Slider (1–3 only).
FR-3.3: Re-renders immediately on any change to Full Name, Scale, Representation Style, or Emoji Set.
3.3.3 Functional Requirements — Dashboard Preview
FR-3.4: A universal semicircular arc gauge (horseshoe), used for every KPI type — not NPS-specific.
FR-3.5: Continuous red → amber → green gradient across the arc; band boundaries are driven by threshold x and y and shift live.
FR-3.6: A large central numeral shows the preview score (the Target value; defaults to the arc midpoint — 50 — when empty).
FR-3.7: The KPI Short Name renders beneath the numeral inside the arc (generic &quot;KPI&quot; in create mode before a short name is entered; &quot;NPS&quot; in edit mode).
FR-3.8: A directional marker (▼) sits on the arc at the target position, coloured by its band.
FR-3.9: Arc range and labels by type: all KPIs except NPS = 0–100 (labels 0/25/50/75/100); NPS = −100 to +100 (labels −100/−50/0/+50/+100); CXI = 0–100.
FR-3.10: Live update triggers: Short Name (label), threshold x/y (band boundaries), Target (marker + numeral), Scale (range set), Calculation Method (internal label).
FR-3.11: When required threshold fields are empty, the gauge renders with defaults (x=20, y=70) and shows: &quot;Using default thresholds — configure fields to update.&quot;
FR-3.12: The gauge is read-only (preview only) and always visible from page load.
FR-3.13: The Dashboard Preview reproduces the M-07 score card and includes, in addition to the gauge: the KPI short name and full name above the gauge; the gauge score with its Target marker and a &quot;Target: [value]&quot; caption; a period-over-period delta with direction (e.g., &quot;vs Last Quarter +4 points&quot;); and a total response count (e.g., &quot;responses 3,420&quot;). These use illustrative sample values in the preview.
FR-3.14: For NPS specifically, the Dashboard Preview also shows the Promoters / Passives / Detractors breakdown as three coloured segments with percentages (e.g., 51% Promoters, 40% Passives, 9% Detractors), reflecting the NPS Standard calculation.
FR-3.15: Question Preview scale anchors: the Minimum Scale Description and Maximum Scale Description values (see Field 5a) render as left/right anchor labels beneath the scale in the Question Preview (e.g., &quot;Definitely Would Not Recommend&quot; … &quot;Definitely Would Recommend&quot;). They update live as the user edits those fields.

3.4 F4 — CXI Composite KPI Configuration
3.4.1 Description &amp; Priority
CXI (Customer Experience Index) is a composite KPI derived from a weighted combination of other active KPIs. It uses the same two-panel layout but replaces scale/representation/method fields with a KPI weights table. Priority: Must-have (CXI is a seeded standard KPI).
3.4.2 Functional Requirements
FR-4.1: CXI's Calculation Method is fixed and read-only: &quot;Weighted Composite&quot;. Scale and Representation Style fields are removed.
FR-4.2: A KPI Weights table lists only currently active KPIs (excluding CXI itself), each with a positive-integer weight input and a live &quot;Effective %&quot; column.
FR-4.3: Weights are relative positive integers; the engine normalises them to proportions at computation time (no sum-to-100 constraint). Minimum 1 per included KPI; 0 = not included.
FR-4.4: &quot;Effective %&quot; and a total row update live as weights change.
FR-4.5: CXI cannot be activated unless at least 2 active KPIs have non-zero weights; otherwise the Active checkbox is disabled with tooltip: &quot;CXI requires at least 2 active KPIs with assigned weights.&quot;
FR-4.6: If an included KPI is deactivated elsewhere, it is auto-removed from the table and proportions recompute.
FR-4.7: Threshold, Target, Active, and Show-on-Dashboard fields behave as for standard KPIs. The gauge renders 0–100; the Question Preview card is hidden (CXI is computed, not surveyed). A proportional weight legend renders beneath the gauge.
FR-4.8: When CXI is shown on the M-07 main dashboard, it displays the composite score together with a member breakdown — each contributing KPI's score and its effective weight (%). M-06 must expose the member breakdown alongside the composite value in the CXI ScoreSnapshot so M-07 can render both.
3.4.3 Business Rules
BR-4.1: CXI always produces a normalised 0–100 score regardless of constituent KPI scales.
BR-4.2: CXI cannot include itself as a constituent.

12.4.4 Tooltip Content (the ? icon per parameter)
Each tooltip gives the CX manager (1) what the parameter does, (2) the valid range and default, and (3) practical guidance on choosing a value.
Alpha (α):
TOOLTIP  Customer importance blend weight. Applies to all journeys in this tenant. Alpha is the weight given to Importance to Customer versus Importance to Business when calculating a touchpoint's weight within its stage. A higher alpha means customer importance counts more; a lower alpha means business importance counts more. Beta is automatically set to (1 − alpha), so the two always sum to 1.0. Range 0.0–1.0, default 0.5 (balanced). Set higher (e.g., 0.7) if your programme prioritises the customer's perspective; set lower if commercial/compliance priorities should dominate scoring.
MOT Multiplier:
TOOLTIP  Score amplification applied to touchpoints flagged as a Moment of Truth (MoT) — the make-or-break interactions that disproportionately shape overall perception. A MoT touchpoint's weight in stage scoring is multiplied by this value; non-MoT touchpoints are unaffected (multiplier of 1.0). Range 1.0–2.0, default 1.5. Use 1.0 to disable MoT amplification entirely; raise toward 2.0 to make Moments of Truth dominate stage scores more strongly. The 2.0 cap prevents a single touchpoint from overwhelming the score.
Responses Count Floor (n_floor):
TOOLTIP  The hard minimum number of responses a touchpoint must collect before its score is trusted. Below this floor, the touchpoint is marked &quot;insufficient&quot;, excluded from scoring entirely, and shown as &quot;—&quot; rather than a number. This protects you from drawing conclusions from too few responses. Default 100. Set higher if your tenant has high response volumes and you want stricter reliability; set lower for low-traffic programmes. It also acts as the flat threshold during a journey's first few weeks before enough history exists for adaptive thresholds.
Flag Percentile:
TOOLTIP  Sets how aggressively low-sample touchpoints are flagged as &quot;low confidence&quot;. The system finds the response count at this percentile across all touchpoints in a journey; any touchpoint below it gets a low-sample badge. Default 25 (the bottom quarter by response volume is flagged). Valid range 1–49. Raise it (e.g., 30 or 32) to apply a stricter standard and flag more touchpoints as low-sample; lower it to flag fewer. This affects display/flagging only — it does not exclude touchpoints from scoring (that's the Responses Count Floor's job).
Rolling Window Days:
TOOLTIP  The time window over which response counts are measured to compute the adaptive confidence thresholds (the median and the flag percentile). It is also the cold-start period: during a new journey's first window, the system falls back to the Responses Count Floor as a flat threshold until enough history accrues. Default 30 days, minimum 7. A 30-day window aligns with the typical expectation that meaningful journey data appears about a month after launch. Use a longer window for slower-moving programmes; a shorter one reacts faster but is noisier.
CONSTRAINT  Tooltips are informational. They must be available on hover (desktop) and on tap (touch), must be fully localized (EN + AR), and must not block interaction with the field.
